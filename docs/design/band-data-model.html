Claudio Band data model

The Convex schema from docs/plans/claudio-band.md §1, and which part of the producer's screen reads and writes each table. For review alongside the UX mockup; nothing here is built yet.

you drums bass keys W2 used from wave 2 client-only never touches Convex

Rules the model obeys

  • Parts are append-only; the newest row plays.Agent turns, picks, history steps, scene recalls and undos all insert. No “current” pointer, so a history step after a scene recall is never ambiguous.
  • Content versions vs copies.Starter, agent, pick and design rows are content: they get a rail pip and basedOn = their own version. History, scene and undo rows are copies that restate a content version's basedOn.
  • One commit, one part row.A multi-tool turn merges into a single version. Mute is not history: muted lives on musicians; solo is client-only.
  • One write rhythm per document.Hot counters live in jamCounters; jams changes only when you edit settings.
  • One conversation = one log, one model, one tool list.Band turns on Sonnet 5 with band tools; design jobs on Opus 5.5 with design tools. messages.convoId is a musician or a design.
  • Library rows are immutable; no presence, no heartbeat.Parts and scenes point at library rows. Turns fire only on your notes and the budget they grant, so an empty room can't loop and cost money.

Gaps / questions for Will

  1. G1 · No way to cancel a design.The headline fallback says “cancel, then pick Glass EP”, but §4 names only designs.start; endDesign is internal, and a pick is refused while the musician is designing. The demo's fallback path needs a public designs.cancel (→ endDesign("cancelled"), which also needs a status value).
  2. G2 · Who writes liveOctave?It's on musicians and goes into the snapshot, but no mutation writes it. Z/X is instant client-side; does every press write to Convex, or only a debounced value?
  3. G3 · The design cutoff has no home.The strip mock reads “iter 2/3” and the headline has a cutoff set by the 1b p50, but designs has no max-iteration or deadline-for-the-whole-job field; turnDeadline is per turn.
  4. G4 · Direct mutations are unnamed.Settings (bpm, key, progression, bars, reactive), mute, scene save/recall, library pick, and the public entry point for C (cancelTurn is described as an internal helper) have no function names. Needed before the convex-test files can be written first.
  5. G5 · “reacting to @bass” can't be read directly.turnCause = nudge says that it's reacting, not to whom. The client would have to find the triggering nudge row in chat; a turnFromMusicianId (or the nudge seq) on musicians would make it a field read.
  6. G6 · The design rail vanishes on finalize.jams.state returns only active designs with attempts. Once a design ends, its distances disappear from the strip; if the soundcheck frame should keep showing “d=18.4 → 11.2” after it lands, the query needs the newest design per musician too.
